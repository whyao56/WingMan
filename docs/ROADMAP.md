## 规划中：通话 / 语音转写

语音识别 / 通话实时转写**已从产品中整体撤下，改为「规划中」**。
上一版试过一版云端转写，能用但不够好：转写延迟、双方串音、断句切得碎，
而且要把通话音频送出本机 —— 对一个「本地优先」的工具，这个代价不划算。
先不放了，思路留在下面，等做扎实再回来。

**已经想清楚的 5 条：**

1. **双通道采集，谁说的要分清。** 一路抓系统回环（WASAPI loopback）当「对方」，
   一路抓默认麦克风当「我」；两条流独立分帧、独立识别，从源头上不把两个人的话混成一段。
2. **本机转写，音频不出机器。** 用 `faster-whisper` 在本地跑，模型权重存到数据目录、可离线；
   代价是首次要下模型、CPU 转写比显卡慢，换来的是一帧录音都不上传。
3. **按「话轮」断句，而不是按静音断。** VAD 先粗切，再用小模型判断句尾是否完整，
   不完整就继续等下一帧 —— 宁可多等几百毫秒，也不切坏一句话。
4. **落库时和文字记录同构。** 转写结果按 `(时间, 说话人, 文本)` 写成普通消息，
   只多带一个 `source=call` 标记，记忆、检索、人物分析都不用为通话写第二套逻辑。
5. **开录前把话说在前面。** 录音涉及法律问题：开始采集前必须明确确认，
   只用于你本人参与的通话、只存本机，不提供「采集他人对话」的用法，这条不做成可关闭的选项。

尚未排期、待做：

| 事项 | 说明 |
|---|---|
| ⬜ 流式转写 | 现在整段转写，计划改成分块流式，降低延迟 |
| ⬜ silero-vad 替换能量阈值 | 音乐 / 噪音环境下能量阈值不可靠 |
| ⬜ AEC 回声消除 | 不戴耳机时麦克风会录到扬声器 |
| ⬜ 录音落盘与回放 | 转写同时保存原始音频，方便核对 |
| ⬜ SSE 实时字幕 | 转写边出边推给前端 |

## 阶段 3：可选进阶（谨慎）

以下涉及平台限制或合规风险，**默认不做**，仅列出供你评估。
其中「读客户端本地库」这一条**已经落地了一部分**，所以单独说明现状：

| 事项 | 风险 | 现状与说明 |
|---|---|---|
| 微信 PC 端数据库直读 | 高 | **已实现**：SQLCipher 4 解密、认列、增量采集全通。**但密钥拿不到** —— 本机实测自动搜内存未命中（83.78M 候选 × 2 套参数各 419 秒），hex 候选 0 处。密钥手工粘贴可走通；不依赖密钥的半自动（剪贴板）是并列通道。仅限本机本人账号 |
| QQ NT 数据库直读 | 中 | **已实现**：剥 1024 字节自定义头 + SQLCipher 解密 + WAL 套用。技术上一路通，卡点同样是密钥。NT 版结构变动频繁，所以认列**按数据认**、不写死映射 |
| ⚠️ 通话录音自动归档 | 中 | 仍未做（语音能力已撤下）。多地法律要求录音前告知对方，务必先确认当地法规 |
| ⚠️ 自动回复（真·代聊） | 高 | 不做。技术简单但伦理风险大：等于冒充你本人跟人交流。**只做「建议 + 一键确认发送」** |

采集侧值得继续做的（不涉及新增风险）：

| 事项 | 说明 | 文件 |
|---|---|---|
| ⬜ 提高自动取密钥命中率 | 现在按签名扫进程内存。可加：已知版本的固定偏移、增大预算、分代扫描 | `app/collect/keys.py` |
| ⬜ 支持矩阵扩充 | 每实测一个新版本就往表里加一行；`SUPPORT_MATRIX` 是数据，加行即可 | `app/collect/matrix.py` |
| ⬜ 半自动支持图片/引用消息 | 现在只抓文本，引用与被引用的上下文会丢 | `app/collect/clipboard.py` |
| ⬜ 采集结果预览与批量撤销 | 采错了要能一次撤掉一批，而不是一条条删 | `routes_collect.py` + `index.html` |

关于最后一条，多说一句：**自动回复这个功能，做出来容易，用起来伤人。**
对方以为在跟你聊天，实际在跟模型聊天 —— 一旦被发现，损失远大于收益。
建议的形态是：模型出选项 → 你点一下 → 内容填进输入框 → **你自己按回车**。
保留了你的决策权，也保留了这段关系的真实性。脚手架的 API 就是按这个形态设计的。

## 建议的下一步（如果你只做一件事）

**阶段 1.1 的「以人为中心」记忆重构已经做完了**（`persons` 表、跨渠道归并、按人取消息），
采集也通了（半自动实测可用）。所以现在真正的瓶颈**不在数据，在质量**。

接着做 **阶段 1.4 的 Prompt 调优**：
其他所有功能都建立在"模型给出的分析够准、建议够好"这个前提上，
如果分析是废话、建议是套话，那再漂亮的前端也没有意义。

方法：从你的真实记录里挑 20 个你已经回复过的片段，
把「对方那句话说出口之前」的状态喂给当前引擎，看它给的选项里有没有你当时真选的那条。
**命中率超过 50% 就说明它真的在理解，而不是在说场面话。**
