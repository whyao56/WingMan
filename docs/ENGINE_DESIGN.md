# 参谋引擎设计

这是项目的灵魂。数据接入、语音、存储都是管道，**只有引擎决定它有没有用**。

本文回答三个问题：
1. 怎么让模型"真的记住"这段关系，而不是每轮都从零开始猜？
2. 怎么让输出的建议可解释、可比较、可信任？
3. 怎么推演"这么回下去会怎样"？

---

## 一、记忆的三种粒度

模型没有记忆，只有上下文窗口。要做长期参谋，必须自己造记忆。分三层：

| 层 | 形式 | 进 Prompt 的方式 | 解决什么 |
|---|---|---|---|
| **L1 事实层** | `facts` 表：`生日=3/14`、`讨厌=被叫宝贝` | 全量注入（通常几十条，几百 token） | 精确信息，不能错 |
| **L2 摘要层** | `summaries` 表：按周/里程碑压缩 | 注入最近 3~5 条 | 长期脉络、大事件 |
| **L3 检索层** | 向量 + 关键词混合召回 | 按当前消息动态召回 top-30 | 细节、当时语境 |

**拼装顺序**（这也是 `analyzer.py` 里的 `build_context()`）：

```
[系统] 你是聊天参谋…
[人物卡]  她叫小鹿，24 岁，做设计，喜欢猫和展
[雷区]    不要叫她宝贝、不要主动提她前任
[目标]    本周内约她看展
[事实]    生日=3/14 · 讨厌=加班 · 猫叫汤圆 · 最近在学陶艺
[时间线]  8/12 第一次约饭 · 8/20 她主动分享加班吐槽 · 9/2 聊到陶艺课
[相关历史]（按当前消息检索出的 30 条原文，带时间戳）
[最近对话]（最近 20 条完整来回）
[当前]    她刚说："哈哈哈今天好累啊"
```

**为什么事实层要全量注入**：几十条事实几百个 token，成本可忽略，
但漏掉一条"她讨厌被叫宝贝"就可能直接毁掉一段关系。**概率成本不对称**。

## 二、分析器 Analyzer

输入：对方的**一条**新消息 + 上面的上下文。
输出结构化 JSON：

```json
{
  "emotion": "轻松愉悦但带点疲惫",
  "emotion_intensity": 7,
  "interest_delta": 1,
  "intent": "吐槽求安慰，同时留了个话头等你接",
  "subtext": "今天过得不太顺，但你回得快，说明她在跟你分享情绪",
  "topics": ["工作压力", "周末安排"],
  "signals": [
    "连用两个语气词『哈哈哈』，情绪放松",
    "主动抛出『今天好累』这种需要回应的球",
    "比平时回复间隔缩短了 40%"
  ],
  "risk": "她提到『周末』但没说有没有空，别立刻硬推邀约",
  "stage_guess": "熟悉期偏暧昧"
}
```

### 设计要点

**1. `interest_delta` 而不是 `interest_score`**
绝对分数（"她对你有 68 分兴趣"）没有意义，也无法标定。
**变化量**才有意义，而且可以用历史统计（回复间隔、消息长度、谁主动开场）来锚定。

**2. `signals` 必须能被引用**
每条信号都要对应上下文里的可观测事实。禁止"她对你印象不错"这种无法验证的结论。
前端把这些信号做成可展开项，点开看到原始消息 —— 让用户能自己判断这条分析靠不靠谱。

**3. 明确区分"观测"与"推测"**
`signals` 是观测，`subtext` 是推测。UI 上用不同颜色分开展示。
这能极大降低用户对模型的盲目信任 —— 而盲目信任一个会幻觉的模型是危险的。

## 三、策略规划 Planner

同样的消息，在不同关系阶段该有不同的目标。

| 关系阶段 | 本轮目标 | 忌 |
|---|---|---|
| 陌生期 | 建立基础好感、找共同点 | 过度热情、连发、盘问 |
| 熟悉期 | 扩大话题面、增加互动频次 | 只聊自己、过于正式 |
| 暧昧期 | 制造专属感、试探边界 | 用力过猛、急着挑明 |
| 推进期 | 落地具体邀约 | 只说不做、反复确认 |
| 稳定期 | 维持温度、深度交流 | 敷衍、只发表情包 |

`planner.py` 输出：

```json
{
  "stage": "暧昧期",
  "goal_this_turn": "接住她的疲惫情绪，顺势把话题引向周末，为邀约铺路",
  "tone": "轻松、有共情但不腻",
  "must_do": ["先回应情绪再谈事", "保留一个开放话头"],
  "must_not": ["立刻问『周末有空吗』", "说教式安慰", "用『宝贝』"]
}
```

## 四、建议生成器 Suggestor

### 4.1 生成策略：先分风格，再生成

不直接让模型"给几个回复" —— 那样出来的几条会高度同质（都是同一个意思换个说法）。
而是**先指定 4~5 种策略风格，各生成一条**，强制发散：

| 风格 | 说明 | 适用场景 |
|---|---|---|
| **接梗调侃** | 顺着对方的话开玩笑 | 情绪轻松时 |
| **真诚共情** | 认真回应情绪 | 对方难过时 |
| **好奇引导** | 提问把球踢回去 | 需要她多说时 |
| **顺势推进** | 自然引出下一步（邀约/见面） | 气氛好且有目标时 |
| **保守稳妥** | 低风险低收益的接话 | 不确定时 |

### 4.2 本地打分（关键设计）

**不让模型给自己打分**。模型对自产内容的自评严重偏高、方差极小，没有区分度。
改用本地可解释启发式：

```python
def score(option, ctx) -> dict:
    naturalness = 长度合理性(option) * 口语化程度(option) * 无AI腔(option)
    warmth      = 情绪回应度(option, ctx.analysis) + 称呼贴合度(option)
    progress    = 目标推进度(option, ctx.persona.goal)
    risk        = 踩雷区(option, persona.taboos) + 用力过猛(option) + 复读对方(option)

    total = 0.3*naturalness + 0.25*warmth + 0.3*progress - 0.35*risk
    return {...}
```

具体检查项（`suggestor.py::local_score`）：

- **长度合理性**：3~25 字最佳，低于 3 字扣分，超过 40 字大幅扣分（聊天不是写作文）
- **口语化**：包含语气词/网络用语的加分
- **无 AI 腔**：命中 `"作为一个"/"首先"/"总的来说"/"希望我的建议"` 等词表直接重罚
- **情绪回应度**：候选里是否出现与 `analysis.topics` 相关的词
- **目标推进度**：是否包含行动动词（约/一起/周末/带你）
- **踩雷区**：命中 `persona.taboos` 中的词，风险直接拉满
- **用力过猛**：感叹号 > 2 个、出现"永远/一直/唯一"等绝对词
- **复读对方**：与对方原话的 n-gram 重合度过高（"哈哈哈今天好累啊" → 回"哈哈哈今天好累啊"）

**这套分数是给"排序"用的，不是给"判断"用的**。UI 上要同时展示分数和扣分理由，
让用户看到「为什么 C 分低」—— 这比一个孤零零的 7.2 有用得多。

### 4.3 输出结构

```json
{
  "id": "A",
  "style": "接梗调侃",
  "text": "那我这儿的门票你要不要买一张，专治加班后遗症",
  "rationale": "先接住她的疲惫，用玩笑话降低沉重感，同时埋下『出门』的钩子",
  "expected_effect": "大概率会被逗笑并顺着接话，气氛继续保持轻松",
  "risk": "如果她今天真的很累，玩笑可能显得没接住",
  "scores": { "naturalness": 0.9, "warmth": 0.6, "progress": 0.5, "risk": 0.1 },
  "total": 7.4,
  "score_notes": ["长度合适", "口语化好", "未命中雷区"],
  "prediction": { "direction": "升温", "confidence": 0.62 }
}
```

## 五、走向推演 Simulator

这是"实时推测聊天会发展到什么样"的实现。

### 5.1 思路

对**每一条候选回复**，让模型扮演对方，往后演 3 轮，输出一棵树。
不是预测唯一未来，而是展示**分叉**：

```
你选 A：「那我这儿的门票你要不要买一张，专治加班后遗症」
│
├─ 分支 1 (58%) 她被逗乐，顺着聊 → 你可以自然引到周末
│   ├─ 她："哈哈哈什么门票"
│   └─ 你："专治加班的那种，周末就开诊"
│       └─ 结局：🎯 成功引出周末话题，邀约窗口打开
│
├─ 分支 2 (27%) 她只回了个表情包，兴致不高
│   ├─ 她："[捂脸]"
│   └─ 建议：不要再追问，换个轻松话题，今天的窗口已过
│       └─ 结局：⚠️ 话题降温，但没伤到关系
│
└─ 分支 3 (15%) 她没接梗，直接说去睡了
    └─ 结局：❌ 今天不适合推进，见好就收
```

### 5.2 实现要点

**（1）用人物卡驱动模拟，而不是自由发挥**
模拟对方时，必须把小鹿的画像、说话风格、当前情绪一起喂进去。
否则模型会演一个通用 AI 而不是"她"。
`samples/` 里的真人对话片段是最好的 few-shot 示例 —— 从历史里抽 5 段她的话作为风格锚点。

**（2）概率怎么来**
模型直接编的数字不可信。做法是：
让模型对每个分支输出 `likely / possible / unlikely` 三档，
映射为 `0.5~0.7 / 0.2~0.4 / 0.05~0.15`，再归一化。
比让模型直接吐 `58%` 稳定得多。

**（3）明确标注这是模拟**
UI 上必须有醒目提示："以下为 AI 推演，不是预测，仅用于比较不同回复的相对优劣。"
**不要把推演结果包装成预言** —— 这是伦理底线，也是产品可信度的来源。

**（4）只推演 3 轮**
推演越深，模型越自由发挥，错误率指数上升。
3 轮刚好够看出「这条回复是让关系升温还是降温」。

## 六、Prompt 工程约定

所有提示词集中在 `engine/prompts.py`。统一遵守：

1. **纯中文** —— 目标场景是中文社交，用中文思考更贴合语境
2. **强约束 JSON 输出** —— 每条 prompt 末尾附 schema，并在 `complete_json()` 里做容错解析
3. **禁止输出歧视、PUA、操纵性话术** —— system prompt 里明确写死这条红线
4. **要求模型标注不确定性** —— 无法从上下文推断的内容必须写"未知"，禁止编造
5. **few-shot 优先用用户自己的历史** —— 从聊天记录里抽 3~5 段真实对话作为风格示例，
   比任何通用示例都有效

### 红线（写死在所有 system prompt 里）

```
你是一位真诚的沟通顾问。你的目标是帮助用户更好地表达真实想法、理解对方感受。

绝对禁止：
- 教授操纵、PUA、情感控制的技巧
- 建议撒谎、伪装人设、假装有某种身份或经历
- 在对方明确拒绝或表达不适后仍建议纠缠、施压
- 生成任何形式的骚扰、贬低、侮辱性内容

如果用户的诉求本身带有上述倾向，直接指出并拒绝，给出更健康的替代方案。
```

## 七、调优建议

| 症状 | 可能原因 | 改哪里 |
|---|---|---|
| 建议都很像 | 没做风格分流 | `prompts.SUGGEST_SYSTEM` 里的风格枚举 |
| 建议太书面 | 模型偏正式 | 加 user 历史做 few-shot；`temperature` 提到 0.9 |
| 分析太泛 | 上下文里 history 太少 | `retriever` 的 `top_k` 提到 50 |
| 记住的信息会漂移 | 事实抽取没带 evidence | `profiler` 里强制要求 evidence 字段 |
| 推演太乐观 | 模型倾向讨好 | prompt 里明确要求"至少给出一个不理想的走向" |
| 分数没区分度 | 各维度权重失衡 | `suggestor.local_score` 里的权重，按需调 |
