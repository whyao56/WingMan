这一版解决的是一个前置问题：**在用它之前，你得先把聊天记录弄进来。**

以前唯一的入口是「导出文件再导入」—— 而 QQ 和微信的官方导出都不顺手。
现在多了两条直接从客户端拿记录的路：一条自动，一条点哪条抓哪条。

---

## 这一版加了什么

### 1. 采集：两条并列的路，不是一条主路加一条备胎

**自动采集** —— 读客户端本地的消息库。QQ NT 和微信 4.x 的库都是 SQLCipher 加密的，
程序会尝试从运行中的进程内存里取密钥，取到就整库读出来，按时间增量落进数据库。

**半自动采集** —— 开启后你**选中几条消息按一次复制**，程序读剪贴板，把
「谁说的 / 说了什么 / 什么时候」拆成结构化记录入库。定位是**给风控和安全问题兜底**
（自动那条路走不通时，它一定走得通），但它同时也是一条正常可用的采集入口。

两条路的数据落点完全一致，都进同一个人、同一条时间线，后面做画像和检索时没有区别。

### 2. 版本支持情况写进软件，而不是写在 README 里

文档不知道你装的是哪个版本，软件知道。所以「你的版本支不支持」这件事做成了
**软件里的数据 + 探测结果**，在采集页直接给你四档结论之一，每一档都带「下一步做什么」：

- **能用** —— 版本在实测范围内，告诉你保持登录、翻一下最近会话
- **能用但我没实测过** —— 版本在范围内但不在实测名单里，告诉你大概率可以、出问题怎么反馈
- **不认识这个版本** —— 客户端更新过了，加密参数可能变了，告诉你去提 issue
- **没装 / 版本太旧** —— 直接说明装哪个版本

支持的是这几个（**实测过的版本只有两个**）：

| 客户端 | 支持的版本区间 | 我实测过的 |
|---|---|---|
| 微信 4.x（进程名 `Weixin.exe`） | 4.0.0 及以上 | **4.1.13.12** |
| 微信 3.x（旧版，进程名 `WeChat.exe`） | 3.0.0 – 3.9.99 | 未实测 |
| QQ NT | 9.9.0 – 9.9.99 | **9.9.20.37051** |

### 3. 数据的诚实性

半自动采集读的是剪贴板，而**剪贴板常常不带时间**。这时候程序不会编一个时间糊上去，
而是二选一（你可以配）：

- 标成「时间推定」，用抓取时刻顶替，但**单独存一个字段**，界面上明确标出来，
  以后能筛掉、能改 —— 因为一旦假时间混进真时间轴，「她平时几点找我说话」这类结论就是错的
- 或者挂起不写，等你填了准确时间再入库

同理，**认不出是谁说的消息不会被瞎猜一个归属**（新版 QQ 多选复制时，第一行往往是
「称呼 + 时间戳」，正文在下一行，这种情况能正确拆开并逐条归属）。认不出就挂起，
等你在界面上指一下是谁说的 —— 不猜。

需要可直接运行的成品，请下载 [v0.2.0](v0.2.0.md)。

原文的下载表格与体积清单已经移除：它们指向的文件已不存在，留着只会让人点到一个
失效的链接。（2026-10-05 那次历史重建已经让本版的附件没能带过来；这次归档又把
0.1.x 剩下的安装包一并撤下，只留文字。）

## 怎么用（3 步）

1. 把 zip **解压到任意位置**（桌面、D 盘都行，路径有中文也没关系）
2. 双击 `WingMan.exe`
3. 界面打开后 →「自检」页，那里会逐条列出还没配好的项，配好一项变绿一项

> ⚠️ **不要只把 `WingMan.exe` 单独拖出来运行。** 旁边的 `_internal` 文件夹是程序本体的一部分，
> 少一个文件都起不来。要挪位置就整个文件夹一起挪。

### 采集具体怎么走

左侧「采集」页，四张卡片从上往下对应四个问题：**我的版本支不支持 → 自动能不能跑 →
采不动怎么办 → 采到哪了**。

- **先看第一张卡**。它会告诉你本机装了什么、什么版本、以及「下一步做什么」。
- **想试自动**：保持客户端登录、主窗口开着，先点「预演」——预演不写库，
  只会告诉你这条链路上哪一步会卡住。预演说取不到密钥，基本就是取不到。
- **半自动更稳**：填好「是谁」（可以选已有的人），点开启，然后到微信/QQ 里
  选中消息按复制。采到的条目会带着「谁说的 / 说了什么 / 时间」出现在下面的列表里；
  认不出说话人的会挂起等你确认。

## 第一次打开可能遇到

**Windows 提示「已保护你的电脑」/ SmartScreen 拦截**
这是**没有花钱买代码签名证书**的正常现象，不是检测到病毒。点「更多信息」→「仍要运行」。
不放心可以先看源码：本仓库全部代码开放，你手上的 exe 就是它打的包。

**数据存在哪？**
`%LOCALAPPDATA%\WingMan\`（即 `C:\Users\你的用户名\AppData\Local\WingMan`）。
聊天记录、画像、设置、日志都在这里。**换个位置解压程序，数据不会丢**——程序和数据是分开存的。
卸载 = 删掉程序文件夹 + 删掉上面那个数据目录。

**双击了没反应？**
在命令行里跑一次：`WingMan.exe --check`
它会直接告诉你缺什么、下一步做什么，报告同时写进**数据目录**的
`%LOCALAPPDATA%\WingMan\logs\selfcheck.txt`（注意是数据目录，不是程序目录）
—— 可以直接把这份文件发给别人帮你看。
打包版没有控制台，所以出错时不会弹窗 —— 这个自检入口就是为这种情况准备的。

## 关于构建的可复现性

**校验和能证明什么、不能证明什么**，说清楚免得你白费力气：

- ✅ **能**证明：你下到的文件是完整的、中间没被改动过 —— 下载中断、缓存污染、被人换过，
  一算就露馅。
- ❌ **不能**靠「自己重新构建一次来复现」。打包这一步本身是确定的（时间戳钉死、文件顺序排序，
  同一份 `dist/` 连打两次字节相同 —— 由
  [`scripts/make_release.py`](https://github.com/whyao56/WingMan/blob/main/scripts/make_release.py)
  保证），但**生成 `dist/` 的 PyInstaller 构建不是逐字节确定的**：同一份源码连构建两次，
  219 个文件里有 **2 个** 不同（`WingMan.exe` 与 `_internal/base_library.zip`）。
  所以你自己跑一遍构建，得到的 zip 校验和一定和上面不一样 —— 那是正常的，不代表哪里坏了。
  换句话说：请拿它核对**下载**，别拿它核对**构建**。

> ⚠️ **这个附件曾在同一个 tag 下换过两次**（本版现已不再提供安装包，所以具体校验和不再列出）。
> 两次替换是同一个原因：示例人物用了真人姓名，而这个仓库是公开的 —— 现在统一改成了
> 虚构的「小鹿」。前两版在包里印着那个名字。功能上三版没有区别，只是名字不同。
>
> 同一个 tag 对应过三个不同的二进制是件容易让人困惑的事，所以写明白，而不是悄悄换掉。
>
> **同一天还重写了一次 git 历史。** 那个姓名不只出现在当前文件里，也已经在历史提交中 ——
> 只改文件是清不掉的，所以给所有历史提交做了同样的替换。
> 结果是：**从引入它的那个提交起，之后 4 个提交的哈希全变了**，更早的没动。
> 如果你在这之前 clone 过，`git pull` 会报分叉，请改用
> `git fetch origin && git reset --hard origin/main`（有本地改动先备份），或者直接重新 clone。
> 老提交在服务端已经不可达。

## 从 0.1.1 升上来

程序和数据是分开存的，**直接下新包解压覆盖旧文件夹即可**，聊天记录和设置都不会丢
（它们在 `%LOCALAPPDATA%\WingMan`）。

升级后多看两眼：

- 侧栏多了一个**「采集」**页 —— 那是这一版的主要新增。
- 首次进采集页会自动探测一次本机客户端，探测不到不会报错，只会显示「没有找到」并告诉你怎么做。

## 这一版还包括

- **人物实体与多渠道时间线**：QQ / 微信 / 导入的记录统一归到「人」下面，
  而不是各自躺在不同的会话里 —— 这是「记住某个人」这件事的前提
- **半自动采集不重复建人**：「小鹿」已存在时会复用那一个，不会点一次多出一个小鹿
- 采集数据与导入数据用同一套去重与检索，「来自采集」只是两个标记字段
  （`chats.source` / `messages.ts_source`），不另起一套
- 一批「不报错但结果不对」的静默故障被修掉（详见 CHANGELOG）

完整清单见 [CHANGELOG.md](https://github.com/whyao56/WingMan/blob/main/CHANGELOG.md)。

## 请先知道这些限制

这个版本**能用，但请把期待放对位置**，说清楚免得你下载后失望：

- **自动采集的「取密钥」这一步，在本机实测没跑通。** 这是最重要的一条：
  我按 SQLCipher 规格穷举了 **8378 万个候选密钥 × 两套参数、每套各跑 419 秒**，
  一个都没命中；按十六进制格式扫描内存的候选，QQ 的 8 个全灭、微信 0 处命中。
  结论是：**这两个客户端当前版本，靠扫描进程内存取密钥走不通。**
  所以在本机实测中，**能确定跑通的是半自动那条路**。
  自动那条路的代码是完整的、解密器有字节级自证的测试，但「在本机真的取到密钥」
  这一步没有成功过 —— 别的机器、别的版本上也许可以，请不要当作已经能用。
- **只实测过两个客户端版本**（微信 4.1.13.12、QQ NT 9.9.20.37051）。
  其它版本会给出结论但没实测过，请以你的实际结果为准。
- **半自动需要你手点。** 它的设计目标就是「一定走得通」，代价是不自动。
- **微信消息库是按需建立的。** 没点开过的会话可能压根没有本地库文件 ——
  这不是故障，先在客户端里翻一下那个会话。
- **读进程内存这件事，部分安全软件会判定为可疑。** 这是自动链路的固有代价，
  请在你的环境里自行评估；不接受就走半自动，那条路只读剪贴板。
- **默认是 Mock 演示引擎。** 不填 API Key 也能跑通全流程，但建议内容是固定规则生成的，
  **不能当真实建议用**。接真模型见 [docs/MODELS.md](https://github.com/whyao56/WingMan/blob/main/docs/MODELS.md)。
- **只做了 Windows。** macOS / Linux 请走源码路线，那条路本身是跨平台的。
- **它只给建议，不代你发消息。** 不做无人值守自动回复 —— 原因见
  [docs/COMPLIANCE.md](https://github.com/whyao56/WingMan/blob/main/docs/COMPLIANCE.md)。
- **采集能力只用于你自己的账号、你自己参与的对话。** 这条不因为「技术上做得到」而放宽。
  详见 [docs/COMPLIANCE.md](https://github.com/whyao56/WingMan/blob/main/docs/COMPLIANCE.md)。
