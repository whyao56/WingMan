这一版有两件事：**「先填、后补」**（对象不必等记录导进来才存在），
以及**「其他聊天」也算数**（QQ / 微信以外的渠道有地方放了）。

另外顺手挖出来并修掉了三个**一直坏着、但没有任何东西会报错**的问题 ——
其中最严重的一个是**「导入微信聊天记录」从项目第一个版本起就是崩的**。

---

## 为什么要改

### 1. 顺序是反的

0.1.4 把记忆的中心从「会话」换成了「对象」，但顺序是**固定的**：必须先把记录导进来，
程序才会替你建出那个对象。可是人的真实顺序常常是反的 —— 你先听说了一个人、
先知道了一些情况（她叫什么、你们是什么关系、你想走到哪一步），**过一阵子**才拿到聊天记录。

于是你会遇到这种情况：想先把「雷区：别提前任」记下来，却发现**没有地方写** ——
因为还没有任何一条聊天记录。

这一版把顺序解开：**先建对象，随时补，之后再用记录去完善它。**

### 2. 「其他聊天」无处安放

以前只有 QQ 和微信两个位置。在 Telegram、钉钉、短信、贴吧里说的话，
要么硬塞进「微信」（之后所有分析都会把来源说错），要么干脆记不下来。

---

## 这一版做了什么

### 1. 对象可以提前新建，只填名字就能建

左栏顶部加了「＋ 新建」。**只填名字就能建**，关系和阶段目标都可以之后再说，也可以一直空着。
对象多起来之后左栏会出现搜索框（按名字 / 别名 / 关系搜）。

左栏每个对象现在显示成两行：名字 + 一行小字（关系 / 最近一句的时间 / 渠道数）。
**还一条记录都没有的对象会明确标出「还没有聊天记录」** —— 否则你分不清「是我建了但没导」
还是「导了但没进去」。

### 2. 对象能右键了

**打开 / 设置… / 重命名… / 合并到… / 删除对象…**

- 「设置…」里字段和新建时一样，**只改填了的**，不会因为改个名字就把关系、阶段清空；
- 「合并到…」用于「QQ 上的小鹿」和「微信上的鹿鹿」其实是同一个人；
- 「删除对象」**只解除归属，不删聊天记录**（确认框里写清楚了这一点）——
  消息是不可再生的，不应该因为删掉一个「人」就永久损失几万条记录。

键盘也能用：`ContextMenu` 键或 `Shift+F10` 打开菜单，方向键选择，`Esc` 关闭。

### 3. 「让 AI 帮我整理」——在你的草稿上补，而不是重写

对象页 →「记忆」→「让 AI 帮我整理」。它把这个人名下**全部渠道**的消息 + 已经记住的事实
合起来交给模型，然后**逐项告诉你它动了什么**：

> 整理完成：新增 12 条事实（共 37 条）。
> 已更新：对方画像。
> **保留了你手写的**：阶段目标、雷区、我的风格。

三条刻意的设计：

- **默认不动你手写的内容。** 你把「雷区：提她前任、叫她宝贝」写得再好，它也不会替你改措辞 ——
  只在你**没写**的地方填。想连手写的一起改写，得再点一次「连我手写的那几项也一起改写」。
- **「保留」是一句保证，不是模型的成绩单。** 你写过的每一项都会被列出来，
  哪怕模型这次对那一项一个字都没提。否则你拿到的就是一份随模型心情浮动的清单，
  少了一项就得自己去比对是不是被改掉了。
- **一个渠道读失败不拖垮其它渠道**，抽样也按渠道配额分（不然话多的那个渠道会把话少的整个盖掉 ——
  而「Ta 在 QQ 上很冷淡」这种结论恰恰只存在于那个话少的渠道里）。

还没导入记录的「提前新建」对象按这个按钮**不会报错**：它会告诉你下一步该做什么。

### 4. 新增「其他聊天」渠道

除 QQ / 微信以外的来源现在是一个**明确定义的位置**，不是「认不出来的东西」：

- **剪贴板采集可以直接选「其他聊天」** —— 内容是你自己复制的，不依赖能否读取加密库，
  所以这一类**采得到**；
- **导入侧认 JSON / CSV**；
- **粘贴文本时能显式选「来源」**（自动判断 / QQ / 微信 / 其他聊天 / 通话 / 当面）。

最后一条的理由值得单独说：**文本排布长得像微信，不等于它来自微信。**
别的聊天工具导出的文本很容易被识别成「微信格式」，于是明明来自 Telegram 的内容被贴上微信标签。
机器猜不出来的事就不猜 —— 一开始问你一句，比事后在渠道设置里返工便宜得多。
**导入完的提示里会写清它归到了哪个渠道**，来源猜错时你当场就能看见。

### 5. 预先建好的对象会接住之后的导入

你先建了一个「小鹿」，之后才导入小鹿的聊天记录 —— 现在这条记录会**挂到你建的那个对象名下**，
而不是冒出一个同名的第二个「小鹿」。

判据是「那个名字下**一段记录都没有**」：空对象里没有任何数据，接住它不可能混掉谁的记忆。
反过来，如果那个名字下**已经有**记录，仍然保守地新建一个（两个「小李」不见得是同一个人），
要不要合并由你显式决定 —— 猜错是静默的，而记忆混在一起比多建一个人严重得多。

## 修掉的三个问题（都是「静默坏了很久」那种）

这一类问题的共同形状是：**编译不报、启动不报、界面照常打开**，
只有真走到那一条路时才出问题 —— 而那条路恰好没有测试。

### 1. 导入微信聊天记录必然崩溃（从第一个版本起就坏）

```
NameError: name 'iter_blocks' is not defined
```

微信适配器引用了一个**从未导入的名字**。所以「导入微信记录」这条路**一直没通过**，
连仓库里自带的 `samples/wechat_sample_阿哲.txt` 都读不出来。

它能坏这么久，是因为当时**没有任何测试跑过微信适配器**。现在两份示例文件都被端到端钉住，
另外加了一条静态守卫：`app/` 下任何模块都不许引用「既没定义也没导入」的全局名
（用标准库 `symtable` 看符号表 —— Python 自己已经算出了这个事实）。

### 2. 通用 JSON / CSV 导入的列名匹配是失效的

代码把「候选列名表」当成了「数据里实际有的列名」，于是永远只返回候选表的**第一个**名字 ——
时间字段叫 `time`（候选表里排第二）读不出来，中文表头 `时间 / 内容 / 发送者` 一个都不中。

最坏的地方在于**嗅探和解析说两套话**：嗅探看到中文表头给 0.85 的高分，
你看到「匹配度很高」，然后一条都没导进去。

### 3. 「检查更新」显示成 0.1.3 —— 不是文案写错，是**进程没退干净**

真正的根因：**一个 0.1.3 时代的旧进程还在 8787 端口答话。**

界面是**每次从磁盘现读**的（所以是新的），而背后答话的服务是一个一直在跑的进程（所以是旧的）。
于是你看到「界面是 0.1.4，它说我装的是 0.1.3」。

除了清掉那个进程，这一版加了三层防呆，让界面**自己发现并说清**这件事：

- 前端自带一个版本号常量 `BUILD`，跟 `/api/health` 报的版本比对，不一致就在页面顶部弹一条红色横幅，
  上面直接写「界面 vX，答话的本机服务 vY」，并给出旧进程的排查步骤；
- `/api/desktop/state` 现在自述 `version / 启动时刻 / 已运行多久 / 是 exe 还是源码 / PID` ——
  旧进程一眼可辨；
- HTML 响应加 `Cache-Control: no-store`，界面不会被浏览器缓存钉在旧版本上。

另外还有一条测试盯着「前端 `BUILD` 必须等于后端 `__version__`」——
否则这道检查会变成天天误报的噪音，你很快就会学会无视它。

### 顺带的几个小修

- **粘贴框里写着的示范格式读不出来**：旁边写着「`2024-01-01 12:00:00 昵称` + 内容」，
  而默认适配器只认 JSON / CSV —— 照着自己界面上的说明粘贴，得到的是一句「没解析出消息」。
  现在默认交给嗅探，并且粘贴内容的后缀从内容推（粘 JSON、粘一张 CSV 都能认）。
- **一条都没解析出来时的提示不会指路**：原来只说「格式不匹配」，等于让你自己猜。
  现在点名这个适配器吃什么，并给出另一条确定能走通的路。
- **全都不匹配时会静默落到注册顺序第一个适配器**（QQ）上，于是提示词也一起说错
  （「「QQ 聊天记录」读不了这份内容」—— 可问题根本不在于它是 QQ）。现在兜底到通用解析器。

## 关于安装包

本版属于 0.1.x 历史归档，**不再提供二进制安装包** —— 只保留这份文字记录。
需要可直接运行的成品，请下载 [v0.2.0](v0.2.0.md)。

原文的下载表格与体积清单已经移除：它们指向的文件已不存在，留着只会让人点到一个
失效的链接。（2026-10-05 那次历史重建已经让本版的附件没能带过来；这次归档又把
0.1.x 剩下的安装包一并撤下，只留文字。）

## 怎么用（3 步）

1. 把 zip **解压到任意位置**（桌面、D 盘都行，路径有中文也没关系）
2. 双击 `WingMan.exe`
3. 界面打开后 →「设置」页最下面就是体检，那里会逐条列出还没配好的项

> ⚠️ **不要只把 `WingMan.exe` 单独拖出来运行。** 旁边的 `_internal` 文件夹是程序本体的
> 一部分，少一个文件都起不来。要挪位置就整个文件夹一起挪。

**想立刻试一下、手上还没有聊天记录？** 不用去找导出文件：
「采集」页最下面有「粘贴文本」，按上面写的格式粘两句话进去就能跑通整条链路。

## 从 0.1.4 升上来

程序和数据是分开存的，**直接下新包解压覆盖旧文件夹即可**，聊天记录和设置都不会丢
（它们在 `%LOCALAPPDATA%\WingMan`）。

数据库迁移是**幂等**的，第一次打开时自动完成。这一版多一步：把历史数据里渠道名写成
`generic` 的记录归一成「其他聊天」—— 归一之前，同一个「其他聊天」在库里有两种写法，
而剪贴板采集是靠在库里找同名渠道来认领的，认不出就会给同一个对象重复建一个渠道。

> **升级后如果「检查更新」还说你装的是旧版本**，八成是旧进程还没退：
> 关掉所有 WingMan 窗口，确认任务管理器里没有残留的 `WingMan.exe`，再打开一次。
> 页面顶部那条红色横幅会直接告诉你它连上的是哪个版本的进程。

## 关于构建的可复现性

**校验和能**证明你下到的文件完整、中途没被换过；**不能**靠「自己重新构建一次」来复现

## 这一版**没有**改的

- **「自动采集取密钥」在本机依然没跑通**，这不是这一版能修的：本机实测（QQ NT
  9.9.20.37051 / 微信 4.1.13.12）按 SQLCipher 规格穷举 8378 万候选未命中，
  十六进制候选 QQ 8 个全灭、微信 0 处。所以**半自动那条路仍是当下确定能跑通的通道**。
- 建议内容的质量仍受限于模型：默认的 Mock 引擎让整条链路能跑，但建议是空的。
  要真实建议请在「设置」里配上自己的模型 API Key。Prompt 调优是下一个阶段的重点。
- 导出**还没覆盖分析留存**（「导出这个对象的全部数据」目前只含消息、事实、画像）。

完整变更清单见 [CHANGELOG.md](https://github.com/whyao56/WingMan/blob/main/CHANGELOG.md)。
