这一版是一次**以「对象」为中心的改版**：把「会话」从主角降成配角，人物成为第一层。
同时把导航从 7 项收敛成 4 项。

---

## 为什么要改

之前的软件是「先有会话、再看会话」。问题是：**同一个人不止一个会话**。

一个人可能在微信上聊、在 QQ 上聊、换过昵称被重新导过一次 —— 这些在旧版里是三个并列的
「会话」，各有一份人物设定、各记各的事实。你会发现自己在做这些事：

- 在微信那个会话里说过「她不喜欢被叫宝贝」，在 QQ 那个会话里又踩一次；
- 想整体看看「她最近的状态」，得自己把两个会话的建议来回翻。

更根本的是，旧版的一级导航是**按功能的来源分的**，不是按用户的意图分的：

```
指挥台 · 记忆 · 导入 · 采集 · 通话（敬请期待）· 自检 · 设置
```

要「导一段记录」得先想清楚「我这算导入还是采集」；想「看看对她的了解」得知道
那叫「记忆」。而「通话」占着一个一级位置却什么都不能做。

---

## 改成什么样

导航 7 项 → **4 项**，每一项都对应一个清楚的意图：

```
指挥台 · 对象 · 采集 · 设置
```

四页的去处：

| 原先 | 现在 | 为什么 |
|---|---|---|
| 记忆 | **并入「对象」** | 人物设定、已记住的事实本来就是「关于某个人」的，不该和会话平级 |
| 导入 | **并入「采集」** | 导入和采集的区别只是「消息从哪来」，分成两页要用户先给自己归类 |
| 自检 | **并入「设置」** | 它是「把软件配好」的一部分 |
| 通话 | **并入「设置 · 关于」** | 此前就是「敬请期待」，占着导航位置名不副实 |

**旧链接不会变成死链**：`?view=memory / import / check / voice` 都做了重定向，
老书签、别人发来的链接、自动化截图脚本都还能用。

## 这一版做了什么

### 1. 「对象」成为第一层，渠道是第二层

左栏变成两级：**对象 → 该对象名下的渠道**。选中一个人，五个 Tab 都在一处：

**概览 / 记忆 / 聊天记录 / 采集 / 历史**

「记忆」把原先散在两处的内容合到一起并**提到对象级**：你手动维护的人物设定
（目标、关系阶段、雷区、说话风格、对方画像），以及模型记住的事实。

事实按 **对象级**与**渠道级**两组显示、**分别计数，不做去重合并**。这是刻意的：
同一条事实在两个视野里各出现一次是正常的 —— 对象级那条是「跨渠道成立」的判断，
渠道级那条是「在这段对话里说过」的记录，合并掉就丢掉了来源。

### 2. 指挥台：先选对象，再勾选渠道（可多选）

**多选渠道时会合并上下文。** 依据是：同一个人在微信和 QQ 上说的，谈的是同一段关系，
只看一个渠道等于只看了半张牌。

合并规则是明确的：

- **主渠道**（你勾的第 1 个）决定人格、昵称与检索锚点，新消息也写进它；
- 事实、摘要、近期消息**跨渠道合并，并按时间归并**；
- 检索是逐渠道做的，再按相关度统一排序 —— 否则话多那个渠道会把话少的整个盖掉。

后端为此新增了 `POST /api/persons/{id}/suggest`（不传 `chat_ids` 就用该对象全部渠道），
`build_context` / `run_analysis` 也改成接受一组 `chat_ids`。**单渠道的旧路径原样保留**，
老用法不受影响。

### 3. 输出会留存

每次分析落一条记录，含**当时用的哪几个渠道**、判断、四条建议、推演。
对象页「历史」Tab 可回看、可展开、可删除。导入 / 采集 / 批量编辑另有一份活动流水。

这一条的意义是：分析结论不是一次性的消耗品。同一句话今天分析过，明天想对比
「当时我是这么理解的，后来她确实是这个反应」—— 之前没地方看。

### 4. 聊天记录可以二次编辑

手动加一条、改角色、改时间、改发送者、全选 / 清空选择、批量删除。

旧版只能整段导入，中间有一条错了只能删库重来 —— 而聊天记录往往是从别处导出来的，
带一两行噪音是常态。

### 5. 半自动采集记的是「消息自己的时刻」

**这一点是用户明确提出来的**：复制一段上周的聊天记录，记成今天是没有意义的。

现在时间来源分 5 类，每条都会标注是怎么来的，界面上可以点开看解释：

| 来源 | 含义 |
|---|---|
| `clipboard` | 复制出来的文本自己带了年月日（最可信） |
| `relative` | 文本里是「昨天 21:03」这类相对时间，按复制那一刻往前推 |
| `inferred` | 完全没带时间，按该会话时间线推定（**新的默认**） |
| `assumed` | 旧的「抓取时刻」，仅用于兼容已有数据 |
| `manual` | 用户手填 |

`inferred` 的做法：锚点取库里最后一条消息，逐秒递增，且**绝不越过复制时刻**
（消息不可能来自未来）。

相对时间的解析有两处刻意收紧，都是被真实文本打脸之后加的：

- **裸钟点只在紧跟称呼之后才认** —— 否则正文里的比分 `3:1` 会被当成时间；
- **算出来的时刻晚于当下就回退一天** —— 「21:03」在上午复制，指的是昨天晚上。

### 6. 导入支持拖放与多文件

窗口任意位置拖入文件即可。多选的文件**逐个导入**，一个失败不会拖垮后面几个，
最后汇总告诉你哪几个成了、哪几个没成。

### 7. 设置页新增「关于」

当前版本、**检查更新**、项目地址、更新日志、许可证。

「检查更新」有一条刻意的设计：**查不到（断网 / 被限流）时说的是「不知道」，
绝不说「已是最新」。** 这是 0.1.3 那个 `Failed to fetch` 留下的教训 ——
把「没查到」和「查到了、没有新版」合并成一句话，就是在骗用户。

### 8. 桌面版右上角 × 会先问一句

**关闭程序 / 关闭弹窗（后台运行）/ 取消**。选过之后按上次的选择走（第二次点 × 直接执行），
不会每次开同一个弹窗。

「后台运行」之后要拿回窗口，**再双击一次 `WingMan.exe`** —— 它会请原来那个进程
把自己的窗口显示出来（`POST /api/desktop/show`），而不是新开一个。

> 这里本来有个不容易发现的坑：如果第二次双击时**新开一个窗口**，那个窗口是个
> **没有服务的空壳**（服务还在第一个进程里）。页面的请求会打到老进程上，于是你在新窗口里
> 点「关闭程序」，关掉的是这个空壳，真正在跑的进程连服务带窗口继续活着 ——
> 用户看到的现象就是「关闭程序失灵了」。所以这里必须是「把原来那个喊回来」。

### 9. 侧栏常驻自检提醒

体检有 warn / fail 时，侧栏底部会出现一条可点的提醒，点一下跳到设置页对应位置；
全绿则整条隐藏。原先自检结果只有进设置页才看得到 —— 而「该配的没配」正是新手卡住的
第一道坎。

## 修掉的两个 bug

### 1. 半自动采集「第一次正常、第二次报错」

```
AttributeError: 'PersonChannel' object has no attribute 'peer_name'
```

建好一个新数据集后，再次选中它点「开始监听」就报这个。`PersonChannel` 少了
`peer_name` / `me_name` 两个字段，**第一次跑时走的路径没碰到它们**，第二次才暴露 ——
所以它看起来是「随机」的。已补字段，并补了一条**真的调 `start()`** 的回归守卫
（原先的测试只调到了内部函数，正好绕过了出事的那一段）。

### 2. 前端调用了不存在的函数（本轮改版自己引入的）

改版时把 `loadChats` 并进了 `loadObjects`，**但漏改了 5 个调用点**。
它的后果不是「一个小按钮失效」：

- 初始化里那一次抛 `ReferenceError`，后面的**读设置、自检、深链接跳转全都不执行**；
- 指挥台那一次在 `try` 里，于是「分析成功」的结果会被 `catch`
  **覆盖成一句 `loadChats is not defined`** —— 看起来就是主功能坏了。

单文件、无构建步骤的前端没有编译器兜底，所以补了一条静态守卫
`test_no_calls_to_undefined_functions`。**它经过反证**：把调用点还原成修复前的写法，
这条守卫会失败。

## 关于安装包

本版属于 0.1.x 历史归档，**不再提供二进制安装包** —— 只保留这份文字记录。
需要可直接运行的成品，请下载 [v0.2.0](v0.2.0.md)。

原文的下载表格与体积清单已经移除：它们指向的文件已不存在，留着只会让人点到一个
失效的链接。（2026-10-05 那次历史重建已经让本版的附件没能带过来；这次归档又把
0.1.x 剩下的安装包一并撤下，只留文字。）

## 怎么用（3 步）

1. 把 zip **解压到任意位置**（桌面、D 盘都行，路径有中文也没关系）
2. 双击 `WingMan.exe`
3. 界面打开后 →「设置」页最下面就是体检，那里会逐条列出还没配好的项

> ⚠️ **不要只把 `WingMan.exe` 单独拖出来运行。** 旁边的 `_internal` 文件夹是程序本体的
> 一部分，少一个文件都起不来。要挪位置就整个文件夹一起挪。

## 从 0.1.x 升上来

程序和数据是分开存的，**直接下新包解压覆盖旧文件夹即可**，聊天记录和设置都不会丢
（它们在 `%LOCALAPPDATA%\WingMan`）。

数据库迁移是**幂等**的，第一次打开时自动完成：新增几张表（画像、分析留存、活动流水），
给消息补一列「采集时刻」，把原先挂在会话上的事实回填到对象名下。
**已有的会话会被自动归到对应对象下**，不需要手工整理。

> 升级后如果发现「自检」页不见了，它没丢 —— 在「设置」页里。
> 「记忆」页也没丢，在「对象」页里。

## 关于构建的可复现性

**校验和能**证明你下到的文件完整、中途没被换过；**不能**靠「自己重新构建一次」来复现
—— 生成 `dist/` 的 PyInstaller 构建不是逐字节确定的（同一份源码连构建两次，219 个文件里
有 2 个不同），所以你自己构建出来的 zip 校验和一定和上面不一样，那是正常的。
详细说明见 [v0.1.2 的发行说明](v0.1.2.md) 里「关于构建的可复现性」一节。

## 这一版**没有**改的

- **「自动采集取密钥」在本机依然没跑通**，这不是这一版能修的：本机实测（QQ NT
  9.9.20.37051 / 微信 4.1.13.12）按 SQLCipher 规格穷举 8378 万候选未命中，
  十六进制候选 QQ 8 个全灭、微信 0 处。所以**半自动那条路仍是当下确定能跑通的通道**。
- 建议内容的质量仍受限于模型：默认的 Mock 引擎让整条链路能跑，但建议是空的。
  要真实建议请在「设置」里配上自己的模型 API Key。Prompt 调优是下一个阶段的重点。

完整变更清单见 [CHANGELOG.md](https://github.com/whyao56/WingMan/blob/main/CHANGELOG.md)。
