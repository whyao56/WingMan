# 合规与隐私

这不是套话。这个项目处理的是**别人的聊天数据**，边界必须在动手前就划清楚。

---

## 一、三条红线

### 1. 只能处理你自己参与的对话

你可以分析你和某个人的聊天记录 —— 因为你是对话的一方，这些内容你有权留存和复盘。

你**不能**：
- 分析你没有参与的对话（即使是你设备上的）
- 分析别人的聊天记录（即使对方同意，也建议谨慎 —— 涉及第三方）
- 用他人设备、账号的数据

**这条红线同样管采集功能。** 采集（自动读客户端本地库 / 半自动监听剪贴板）只是换了个
「数据怎么进来」的入口，不改变上面这条边界 —— **进来的必须是你自己参与的对话**：

- 采集**只读本机、只读当前登录账号**的库，不做任何取证式的「扒别人的机器」；
- 密钥只允许来自**你自己的进程内存**（那是你自己登录的客户端）或你自己粘贴；
- 采集**不联网**，也**不上传**任何原始数据（只有你显式配置了云端 LLM 时，检索上下文才会出去）；
- 半自动剪贴板模式更严格：它只能拿到**你自己复制过**的内容 —— 你复制什么，它就只抓什么。

换句话说：采集解决的是「本机有没有能力把数据读出来」，而不是「能不能读到不属于你的数据」。

### 2. 通话录音的合规边界（目前未提供；将来若提供，红线如下）

**这个能力目前没有提供。** 语音识别 / 通话实时转写已从产品中整体撤下，改为「规划中」，
当前版本不采集、不存储任何通话音频，控制台里也没有相关入口。

下面这组要求是为**将来的实现**预留的约束 —— 如果以后重做这个能力，必须照此执行。

实时监听通话涉及录音，各地规定差异很大：

- 中国大陆：司法实践中，一方当事人对自己参与的对话进行录音，通常不认定为非法。
  但**传播、公开**可能触犯法律。
- 部分国家和地区（如美国部分州、欧盟部分地区）要求**双方同意**才可录音。

**将来实现时**：开始采集前必须先做明确确认，只用于你本人参与的通话、只存本机，
且不做成可以关掉的选项（详见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3.5 节）。
**请你自己确认所在地的法律。** 如果不确定，保险做法是告知对方你在记录，
或者只用于个人备忘、绝不外传。

### 3. 数据默认不出本机

WingMan 的设计是本地优先：原始消息、画像与设置全部存在 `backend/data/`。
（通话录音相关的能力目前没有提供，本机不会生成这类文件。）

**但是注意**：如果你配置了**云端大模型**（DeepSeek / OpenAI 等），
那么你发给它的每一条消息、以及检索出的历史上下文，**都会上传到该服务商**。

这是必须清楚的取舍：

| 配置 | 隐私 | 效果 |
|---|---|---|
| Mock Provider | 完全本地 | 演示用，无真实智能 |
| Ollama 本地模型 | **完全本地** | 能力弱一些，需显卡 |
| 云端 LLM | 消息与检索上下文上传到服务商 | 效果最好 |

**如果聊天的内容对你很重要，请用全本地方案。** 这也是项目把 Provider 做成可切换的原因。

## 二、代码里的合规实现

脚手架已经在这些地方做了约束：

| 位置 | 做法 |
|---|---|
| `.gitignore` | 屏蔽 `backend/data/`、`samples/private/`、所有音频与导出文件，防止误提交 |
| `engine/prompts.py` | 所有 system prompt 内置红线，禁止操纵/PUA/谎报身份/纠缠 |
| `simulator.py` | 推演结果强制标注"这是模拟，不是预测" |
| API | 不做任何外发数据的定时任务，不内置遥测 |
| `collect/semi.py` | `assume_peer`（认不出说话人就当对方）**默认关**；认不出就挂起等你确认，不猜 |
| `collect/semi.py` | 剪贴板没带时间戳时用抓取时刻顶替，但必须标 `ts_source='assumed'` 单独存列 —— 不让人把推定时间当成真时间 |
| `collect/sqlcipher.py` | 解密认证失败返回 `None`（fail-closed），不返回半个看似正常的结果 |
| `collect/keys.py` | 只扫 `QQ.exe` / `Weixin.exe` 这两个本机进程的内存；结果如实报「没扫到」还是「时间不够」，不夸大 |
| `collect/pipeline.py` | 采集不联网；解密副本与缓存全部落在本机 `backend/data/collect_cache/` |

> 语音 / 录音能力已撤下（改为「规划中」），当前版本没有任何通话采集入口，
> 所以上表不再有对应的 `asr/` 条目。将来若重做，约束是：开录前必须明确确认、
> 只用于本人参与的通话、只存本机，且不做成可关闭的选项。
>
> 注意区分：**读取本机的聊天文本库（已提供）** 与 **录制通话音频（未提供）** 是两件事。
> 前者是你自己参与过的文字记录，后者涉及他人声音的录音，法律要求更严 —— 所以后者仍然不做。

## 三、关于「自动回复」的立场

需求里提到"自动回复"。脚手架的立场是：

> **提供建议和一键填充，不提供无人值守的自动代聊。**

原因不是技术做不到，是它会造成实质伤害：

1. **对方以为在和你交流。** 这是欺骗，不是效率工具。
2. **关系的价值来自真实。** 用模型代聊得到的"好感"是假的，你也没从中成长。
3. **一旦暴露，信任崩塌。** 这是不可逆的损失。

所以 API 层面的形态是：

```
模型出候选 → 你选择 → 落到你的输入框 → 你确认后发送
```

决策权和责任都留在人手里。

如果你确实需要"我只想点一下就发"，那也应该是**你逐条确认**的，
而不是"设定好之后让它自己聊一天"。

## 四、给 fork 者的提醒

如果你要把这个项目开源或分发：

- 在 README 保留免责声明
- 不要附带任何真实聊天记录样例（`samples/` 里的都是虚构的）
- 不要删除 `engine/prompts.py` 里的红线段落
- 如果你的分支加入了数据库直读、自动代聊等能力，请自行承担合规责任，并明确告知使用者风险

---

## 五、一句话总结

> 这个工具应该让你**更会说话**，而不是**不用说话**。
>
> 如果用了它之后，你对自己说的话越来越不负责，那它就是失败的设计。
